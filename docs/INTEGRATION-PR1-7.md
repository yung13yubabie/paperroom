# 紙間草稿整合驗收

這個暫時分支只供整合測試。整合順序為草稿 #1、#2、#3，再依共同基底加入 #4 的群組、#5 的集合排序、#6 的 Vault 預覽與 #7 的 Canvas 位置。Git 父提交保留各草稿的歷史。

- #1 `a923d79`、#2 `f9cabe2`、#3 `d29627c`
- #4 `9cf4a6d`、#5 `1188540`、#6 `2f087c5`、#7 `d43084a`

Canvas 投影保留前 500 個節點的原有繪製上限。群組移動用完整幾何資料找成員，定位與選取外框則用實際繪製的位置。整合分支使用一般未簽章 CI 建置，歷史的單一功能重播仍各自留在對應的草稿提交。

## 同一份 Vault 的操作驗收

1. 在檔案選單預覽 Obsidian Markdown 資料夾。確認同名筆記的歧義與缺件提示。取消後不應寫入工作區。預覽後若有附件變更，紙間會要求重新預覽。
2. 匯入繁中路徑與附件。從 A 開啟同名筆記 B 的精確標題，插入指定 B 的紙間連結，然後在紙間改名 B。Canvas 綁定同一批 Vault。從 A 找到兩個節點位置，各自置中，再開回 A。
3. 將同一對 A、B 加入集合，以數字公式保存表格排序。關閉再開，核對列順序與 Canvas 位置。
4. 匯出可攜 Vault ZIP。以同一個 EXE 開另一個空工作區。改過內容與清單校驗不符的 ZIP 應被拒絕，資料保持原樣。匯入有效 ZIP，重開後分別驗證相對標題與身分連結找到同一篇 B，並核對 ZIP、附件及原 Vault 檔案。
5. Vault ZIP 攜帶筆記、來源附件、顯示標題與可重綁連結。Canvas 和集合檢視由工作區保存，可用工作區備份攜帶。

原生流程由 `scripts/windows-highlight-workflow.ps1 -Exe <Paperroom.exe> -ExeSha256 <SHA-256>` 執行。測試使用合成的實體檔案和真正的 Windows 選單、對話框、鍵鼠與原生繪圖，SQLite 只讀核對持久資料。Windows Server CI 的結果適用於該環境。正式發佈另需乾淨 Windows 10／11 客戶端斷網驗收與 Microsoft 靜態 VC CRT 再散布確認。
