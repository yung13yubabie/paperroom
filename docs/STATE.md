# 資料、暫存與離線使用

這份清單依紙間程式碼整理應用程式直接管理的狀態，並非 Windows 所有背景檔案或系統紀錄的完整清單。筆記及備份是明文，請用 Windows 帳戶權限及安全的備份位置保護。

## 資料位置

啟動時以執行檔實際位置為準，不以命令列目前工作目錄選擇資料夾。如果帶 `--portable` 參數，或執行檔旁已存在 `paperroom-data` 資料夾，使用該資料夾；否則使用 `%LOCALAPPDATA%\Paperroom`。帶參數時程式會嘗試建立資料夾。工作區請放在本機磁碟。程式在建立工作區及開啟資料庫前核對目錄解析後的磁碟，並拒絕把個別資料庫或 SQLite 旁檔指向其他位置。指向同機可用磁碟的資料夾別名仍可使用。`LOCALAPPDATA` 缺失、空白或不是絕對路徑時會顯示啟動錯誤，不會退回目前工作目錄；資料夾無法建立或資料庫無法開啟時也會顯示錯誤。 初始化和遷移前會確認 SQLite 實際回報 WAL；若無法啟用，紙間會停止開啟工作區。左側狀態顯示「本機工作區」或「可攜工作區」；搜尋時該處顯示結果數。選擇「檔案 → 開啟資料所在資料夾」可確認位置。

- **持久資料**：`notes.sqlite3` 保存筆記標題、正文、階層、標星、垃圾桶狀態及版本，也保存白板卡片和座標。資料庫內另有階層與垃圾桶索引及結構版本，供程式查詢和升級使用。若資料庫版本比程式支援的版本新，程式會拒絕開啟，並在變更日誌模式之前檢查版本；請使用較新版本開啟，保留原資料。
- **SQLite 工作檔**：程式使用 WAL 模式，執行期間資料庫旁可能出現 `notes.sqlite3-wal` 與 `notes.sqlite3-shm`；SQLite 的鎖及復原狀態由 SQLite 管理。不要手動刪除這些檔案，WAL 可能含尚未合併的已提交資料。Wine 的首次建立測試也觀察到選定工作區短暫出現 `notes.sqlite3-journal`；它同樣由 SQLite 管理。其他 SQLite 日誌是否出現取決於資料庫與執行環境，不應當成可任意刪除的垃圾。
- **使用者選定的輸出**：工作區備份是完整資料庫快照；Markdown 匯出是單篇文字。它們保留在選擇的目的地，不是暫存檔。請定期另存備份並確認可以開啟。
- **匯出中的暫存**：備份或匯出時，程式在目的地旁建立 `.paperroom-<PID>-<序號>.partial/`，內含暫存名稱 `output`。正常完成或錯誤時會嘗試清理；突發終止可能留下目錄。先關閉所有紙間視窗，確認該目錄是中斷作業的輸出且無需保留，才刪除整個目錄。輸出目標已存在時程式拒絕覆寫，請選新名稱。

備份可在另一個資料夾的 `Paperroom.exe` 旁建立 `paperroom-data`，把備份複製成其中的 `notes.sqlite3`，再開啟那份程式檢視。複製或攜走工作區前請正常關閉所有紙間視窗；若有重要資料，優先使用程式內的備份功能，並保留原檔。

## 複製筆記與 Notion 原始 CSV

副本有自己的筆記及附件 ID。正文照原樣複製，紙間識別碼及已確立的舊標題連結仍指向原筆記。未綁定的標題連結遇到副本的同名頁時可能無法唯一解析。Vault 相對連結的解析取決於原來的匯入位置。集合與白板配置、關聯欄位、PDF 標註及原頁歷史均留在原頁。工作區備份會保存副本。

Notion ZIP 裡的 UTF-8 CSV 會在「Notion 原始 CSV」分組各保存一份附件，並保留包內位置。同資料夾或巢狀 ZIP 的來源可分辨。另存附件後可用「匯入 CSV 表格」建立文字欄位。CSV 的關聯網址只當文字保存。

## 工作區第 23 版候選

匯入的 Zotero CSL JSON 原檔保存為批次根筆記的附件，整份 SQLite 備份會保留附件及批次身分。修改下層書目筆記會保留原始檔快照。刪掉原始附件後，批次會失去原始匯出入口。單篇筆記與附件 ZIP 可保存附件位元，回匯後可從附件清單另存。

心智圖的父子關係及畫面座標隨 SQLite 備份保存。HTML ZIP 是某次匯出的閱讀版，包含使用中的筆記、階層導覽、原始 Markdown 及附件。用 SQLite 備份保留垃圾桶、白板、PDF 標註與集合檢視。

## 同步區塊與日誌的保存方式

同步區塊的位置存在引用筆記的 Markdown，原文和版本記錄仍在來源筆記。閱讀時才讀取來源。同一工作區的引用使用筆記識別碼和區塊 ID，完整 SQLite 備份會一起保存。單篇 Markdown 匯出只帶原文或引用標記，移到其他工作區時請一併使用工作區備份。

Vault 的文字嵌入在同一次匯入的筆記中解析，來源改動須先存至紙間工作區才會出現在閱讀模式。相同路徑或區塊 ID 無法唯一判定時會顯示原因。可在垃圾桶還原來源。解除同步時，紙間只會將選定那一處換成目前的 Markdown。若內容含其他區塊 ID、連結或嵌入，請到來源手動複製需要的內容。

日誌月曆只讀取原有的日誌日期身分及已存的 Markdown 待辦。點選空白日期才建立日誌，開啟月曆、換月及取消均無須寫入。兩項功能沿用第 22 版資料庫格式。

## 工作區第 22 版候選

每張白板的最近一次排列會保存於工作區。復原前會重新核對原卡片與物件的位置、尺寸和版本。若參與排列的卡片已移動、縮放或移出白板，該次復原紀錄即失效。若復原位置已有人占用，程式會保留現在的排列。此項操作和復原資料隨 SQLite 備份保存。

跨頁待辦從已保存的 Markdown 讀取清單。切換勾選只會改動原筆記的單一標記，並沿用筆記版本記錄。Vault 未連結提及也會在確認後保存到工作區的來源筆記，原 Vault 檔案在此流程中只供匯入。新版具名檢視新增週及月的條件碼，只有重新套用檢視時才以本機日期計算。請用現行版本備份，再以備份副本開啟新版。

## 工作區第 21 版候選

圖片卡使用筆記 ID、原始圖片附件及各白板的卡片尺寸。從白板移出卡片後，工作區仍保留它的筆記和附件。剪貼簿像素轉存為 PNG，檔案貼上則保留位元。縮圖快取只在視窗記憶體。圖片受既有附件額度限制，每檔最多 8 MiB，工作區合計 128 MiB。

範本可保存多層 Markdown 子頁，舊範本的直接子頁位置沿用原值。具名檢視只保存相對日期條件，每次重新查詢按本機日期計算。標籤面板的排序、展開及查詢字詞隨面板關閉清除。

研究 ZIP 只有使用者選定的輸出檔，發布前沿用目的地同磁碟的原子匯出流程。匯入直接讀 ZIP 並以單筆交易建立白板，新白板資料隨工作區備份保存。可以解壓 ZIP 到空 Vault 看標準的 Board.canvas 和同批檔案。工作區的完整移轉仍使用 SQLite 備份。

## 工作區第 20 版候選

第 20 版會保存範本中明確選定的直接子頁標題與 Markdown 快照。套用時可選擇是否帶入這些子頁。每次建立的子頁都有自己的 ID，保存的範圍限於所選直接子頁的標題及正文。範本根頁原本明確選定的資源仍由獨立確認步驟處理。候選亦可建立不依賴資料列的空白範本，並在新建或編輯範本時加入尚未選取的已宣告型別欄位預設值。保存範本本身不建立筆記。每個範本最多 64 個直接子頁，根頁與子頁正文合計最多 4 MiB。存入範本前請先移除連結、嵌入及 HTML。

第 20 版資料庫會為每篇筆記保留內部身分碼，工作區備份也會保存它。新複製的區塊連結同時核對筆記 ID 和身分碼，防止另一個工作區的同 ID 筆記被誤開。Markdown 單篇匯入會建立新筆記身分，原工作區連結需要整份 SQLite 備份才能一起恢復。

第 36 版不會改寫 Markdown 的舊式連結文字。新匯入的筆記若只寫舊式數字 ID，該文字不會變成可跳轉或反向連結。升級會為當時正文內可比對的舊式連結保留目標身分，已有外部來源紀錄的 Vault 與 Notion 筆記除外。過往單篇或一般 ZIP 匯入沒有來源標記，無法回溯區分，升級時沿用原有解析。若要補一筆連結，請在紙間用「插入筆記連結」重新選取目標。

從 F6 複製區塊連結時，紙間會把文字送到 Windows 剪貼簿。剪貼簿歷程由 Windows 設定管理。

開啟候選前請用舊版備份工作區，再以副本測試。若需回退，請使用升級前的備份。

## 工作區第 19 版

工作區新增資源表，保存範本中明確選定的本機關聯與附件來源。舊範本升級後仍維持原欄位與正文，資源清單為空。套用時可選只帶入原有內容，也可明確選擇一併帶入資源。新增筆記、關聯及附件在同一交易寫入。請先用現行版本備份，再用副本開啟新版。

## 工作區第 18 版

第 18 版將資料列範本保存在集合的工作區資料庫。套用範本會建立新的筆記及集合資料列。修改新筆記不會寫回範本或來源。區塊連結的返回位置只保存在目前執行階段。請先用現行版本備份，再以副本開啟候選。

## 工作區第 17 版

工作區第 17 版可在具名檢視保存公式、關聯和彙總條件。檢視開啟時按當下的筆記及欄位值計算，不保存過去的計算結果。第 16 版仍可開啟升級前的備份副本。請先備份，再用新版開啟工作區。

## 工作區第 16 版

工作區第 16 版可保存帶有 AND／OR 群組的集合篩選。既有具名檢視、欄位和篩選保留，原有集合資料不需搬移。第 15 版程式會拒絕開啟這個版本的工作區。若要回到舊版，請用升級前的備份副本。

## 工作區第 15 版

第 15 版新增雙頁摘錄的第二組來源頁和選區。既有單頁摘錄用原方式開啟。雙頁摘錄卡保留兩頁的引文和選區，原標註移除後，只要 PDF 仍可讀，兩頁都可從卡上預覽。文件本身移除後，卡片仍可編輯。升級前請保留舊版備份，回到舊版時請用該備份的副本。

## 工作區第 14 版

時間軸月份、已儲存檢視及相鄰頁 PDF 的配對都保存在同一工作區。第 14 版加入新欄位與資料表。若要回退，請用舊版另存的工作區備份副本。

- 相鄰頁選取在按下保存前只保留在目前 PDF 視窗。保存時會比對 PDF 的原始位元，並同時建立兩個頁內標註。任一步失敗都會回滾。移除一頁標註會解除配對，另一頁保留。
- 白板多選和分區收合屬於目前視窗的操作狀態。確認成組移動後，所有新座標一起寫入工作區。收合的成員仍保有自己的位置。
- 核對 Vault 外部搬移會先比較已匯入的共同版本、原路徑及新路徑。預覽後須另存完整工作區備份。確認時會再次查核變更，只有能驗證的連結更新及來源路徑會寫進 SQLite。原磁碟檔由使用者選擇的外部工具管理。

## 工作區第 13 版的復原資料

這份候選首次開啟舊工作區時，會在同一筆 SQLite 交易中升級集合檢視、改名連結、白板及 PDF 摘錄的資料表。升級前先用舊程式輸出工作區備份，若需回退則開啟升級前備份的副本。

- 原本能唯一辨識的本機純標題 WikiLink，在目標改名後以筆記 ID 解析。對應關係保存在 SQLite 備份。Markdown 匯出保留原文字，Vault 的實體檔名和連結原稿也維持原樣。儲存時若需解析的正文超過 64 MiB，會保留舊標題、舊連結和編輯中的文字。
- 每張白板保存最近一次移除的文字方塊，包括正文與原位置。再次移除會取代該板的待復原資料，成功復原後會清除它。
- PDF 摘錄保留原標註的引文、註解及座標，指向同一則標註的摘錄卡共用資料。只有原 PDF 仍在且來源筆記可開啟時才能復原標註。工作區備份會含這些資料。永久刪除該來源的最後一張摘錄卡時，程式會移除相應的復原資料。由舊版遷移前已失去標註的摘錄卡只保留卡片正文。

## 工作區第 12 版與筆記版本

第 12 版加入子白板、白板文字方塊、集合週曆、清單與筆記版本。第 13 版沿用這些資料。

第 12 版起，標題或正文改動前會寫入歷史。工作區第 32 版也在改動屬性或附件時保存版本。升級前的快照照常可用，只還原標題與正文。新版快照另保存屬性值及附件的身分、檔名、來源路徑和原始位元。移除目前的附件後，舊快照仍可保留該附件。

每篇最多保留 30 份快照，全工作區最多 2,048 份，合計最多 192 MiB 歷史內容。額度包含重複存入的附件內容。超過上限時會移除較舊的快照。還原前保存的快照同樣受此限制。SQLite 檔案大小也受目前資料、索引與已分配空間影響。完整工作區備份會包含仍保留的快照。Markdown 或 Vault ZIP 只匯出各自支援的內容。

## 工作區第 35 版與具名檢視的分組收合

收合以檢視、分組欄位、欄位型別及群組原值保存。空白群組有獨立記錄。篩選暫時隱藏某個群組時會保留其設定。工作區備份會包含收合記錄，較舊的程式請使用升級前的備份副本。

## 工作區第 34 版與集合欄位顯示

每個集合可選擇表格及清單上顯示的現有屬性及排列。紙間只保存欄位名稱和順序，不另存欄值。新集合及升級前的集合沿用原有畫面，直到使用者儲存設定。完整工作區備份會保留這份配置。若需以舊版開啟，請使用升級前的備份副本。

## 工作區第 33 版與相對日期篩選

具名檢視保存日期條件，套用時依本機日期計算。本版新增「未來七天」及「逾期」兩個條件。既有檢視、屬性定義與匯入資料維持原樣。先用舊程式備份，再用新程式開啟副本。若需使用舊程式，請開啟升級前的備份副本。

## Vault 批次讀入

先選已匯入的紙間 Vault，再明確選取對應本機資料夾。預覽以原匯入路徑配對，可用 `?列號` 查看第一處差異附近的兩份原文。套用「安全」只更新磁碟單方變更及雙方一致的項目。明確選擇衝突列時，將磁碟版另存一篇紙間筆記，保留紙間原文。缺檔以及磁碟中尚未配對的文件在預覽列出。

套用前另存一份工作區備份，紙間重新掃描磁碟，並在 SQLite 交易內比對原預覽。預覽後的磁碟差異或紙間變更會使套用停止。此入口處理磁碟讀入，寫回使用下一節的入口。附件增量同步與自動監看待做。第 8 版資料庫尚無同步基準，同路徑雙方原文一致時可建立基準，內容不同時可略過或保留兩份。

## 更新 Vault 來源附件

先開啟含來源附件的匯入筆記，再從「檔案 → 更新 Vault 來源附件」選取附件，指定原 Vault 資料夾。預覽會列出相對路徑、會更新的副本數與新舊容量。確認後須另存一份完整工作區備份。可用該備份的副本開啟更新前的工作區。

程式會再讀一次來源檔並重核紙間資料。只更新該匯入批次內同一路徑且內容一致的副本，附件 ID 沿用原值，磁碟原檔保持原樣。若預覽後路徑或內容再次變動、筆記有未協調差異，或 PDF 有仍可定位的標註或摘錄，程式會停止更新。若已建立備份，後續錯誤會列出該備份位置。

## Vault 批次寫回磁碟

從「檔案 → Vault 批次寫回磁碟」進入。先選紙間已匯入的 Vault 和對應本機資料夾，預覽後可輸入 `?列號` 對照，選擇「安全」或明確列號，確認寫回並選新的 SQLite 工作區備份。只有路徑已配對、共同基準經確認且只有紙間一方變更的既有檔案可寫回；衝突、缺檔或基準不明的項目不寫回。磁碟版本可另用「檔案 → 預覽筆記庫批次同步」讀入或保留兩份。

每次實際改寫都會在原檔同一資料夾建立新的明文 `.paperroom-recovery-…-原檔名.bak`，保存這次改寫前的完整原文。先前的 `.bak` 會保留，重新掃描時會當作隱藏復原檔略過。混合換行的變更及無法安全建立復原檔的過長檔名會被拒絕。

紙間在每次套用前，另把完整工作區備份到你選的新 SQLite 檔。備份是明文，包含其他筆記與附件。選擇保留衝突兩份時，磁碟稿會存成工作區內另一篇筆記，之後的工作區備份也會包含它。同一份磁碟內容重掃時會保留先前結果。若磁碟再次改變並產生新衝突，重新選擇保留兩份會再新增一篇。若原檔或備份位置由外部服務同步，這些明文資料可能依該服務的設定上傳或留下歷史版本。

突發中止可能只完成部分檔案。錯誤訊息會分別列出已確認完成的檔案與復原路徑、處理中停止而需核對的檔案，以及尚未嘗試的檔案。資料庫交易失敗時，已寫回的磁碟檔仍會保留，資料庫基準會回到原值。再操作前保留 `.bak` 並重新預覽。若兩端已一致，可用「預覽筆記庫批次同步」記錄共同版本。若不同，逐檔比對，再按需要從復原檔取回相應舊稿。[本輪候選驗收](UI-ACCEPTANCE.md)

## 原地編輯 Markdown

「檔案 → 編輯 Vault Markdown 原檔」每次只操作使用者選取的一個本機 Markdown 檔。開啟時記住檔案身分及原始位元。確認寫回前，紙間以 Windows 檔案分享限制排除其他寫入或刪除，核對完整原文。若外部版本有變更，畫面保留可複製的草稿和錯誤訊息。單一換行格式及 UTF-8 BOM 會保存。

原地寫入前會在同資料夾建立唯一的 `.paperroom-recovery-*.bak`，同步內容後讀回比對。原地寫入途中斷電可能留下部分原檔。若發生這種情況，請保留現場兩份檔案，核對同資料夾的復原檔，再用其內容復原。復原檔會保留供使用者檢查。這個入口和 SQLite 工作區各自保存。

## 工作區第 37 版與來源匯入

工作區保存標記為 Heptabase 的 Markdown 匯入根目錄，以及 Bases 欄位定義和各集合成員的檔案快照。Bases 檔案和 Markdown 頁首快照只供該集合顯示，不會寫入原筆記、參與屬性公式或套用同名屬性的篩選。匯入後才加入集合的筆記沒有這份快照。完整工作區備份會保存這些資料。舊版程式無法開啟第 37 版資料庫，升級前請先另存備份。

## 視窗內狀態與中斷

編輯內容先留在視窗記憶體；停止輸入約 550 毫秒後觸發自動儲存，也可按 `Ctrl+S`。在成功儲存前強制結束可能遺失尚未寫入的修改。搜尋詞、目前頁面、閱讀／編輯和白板畫面等是視窗內狀態；白板卡片及座標則存入資料庫。

儲存失敗時狀態列會顯示錯誤，編輯文字留在視窗中。請先複製修改，再處理磁碟空間、權限等問題並重試。兩個視窗編輯同一舊版本時，後送的修改會被拒絕：先複製該視窗的文字，再重新開啟頁面並合併修改。正常關閉時若儲存仍失敗，程式會詢問是否捨棄修改；選擇捨棄才關閉。Windows 要求結束工作階段時，程式會嘗試立即儲存，失敗時向系統回報；系統最終行為仍取決於 Windows。

## 系統與網路

目前程式碼使用 Windows 原生控制項、系統 RichEdit 與檔案對話框；SQLite 編入程式。程式本身的筆記與白板操作不需要登入或網路，程式碼中未見應用程式自行發送網路請求。這不是對 Windows、檔案對話框、系統安全軟體、網路磁碟或其他外部元件活動的保證。程式未實作自有的登錄檔設定；Windows 仍可能自行管理對話框及其他系統狀態，程式要求檔案對話框不要改變目前工作目錄或加入最近項目。程式動態查找 DPI 功能；查詢 API 不存在時使用 96 DPI 作為後備值，這不保證所有舊版 Windows 均可執行。

Linux 主機測試通過 13 項；Windows 測試程式在 Wine 10 UTF-8 環境通過 16 項，涵蓋長 Unicode 路徑、Markdown 匯出、SQLite 備份與重開、控制項及工作區路徑。斷網 Wine 測試涵蓋預設及可攜工作區、正常退出與強制結束後重啟、中文筆記與搜尋，以及 Notion ZIP 父頁和子頁匯入。同一份 v0.1.1 EXE 也在 GitHub 的 Windows Server 2022 runner 通過預設與可攜模式的首啟、儲存及中斷復原測試。Windows 10／11 標準帳戶、實體中文輸入法與 SmartScreen 提示仍待驗證。詳細結果與限制見 [驗證紀錄](VERIFICATION.md)。

執行檔未經 Authenticode 簽章。下載後若遭 Windows 或組織政策阻擋，可先核對發行頁 SHA-256，再將實際錯誤、Windows 版本與雜湊提供給管理員；雜湊無法代替簽章信任。尚未在原生 Windows 觀察 SmartScreen 的實際提示或阻擋結果，不應假設每台電腦會出現相同畫面。
