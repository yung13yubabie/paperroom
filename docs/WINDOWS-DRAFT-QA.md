# 紙間 Windows 草稿驗收

使用新建的合成工作區。先比對候選 EXE 的 SHA-256。獨立的草稿驗收會下載已核對的 CI 附件，檢查版本及雜湊，再在 Windows Server 2022 操作同一份 EXE。乾淨 Windows 10／11 的驗收需要在無網路的測試機另跑。

## 高亮、備份還原及 HTML

1. 將測試 EXE 複製到空白資料夾並以 `--portable` 啟動。新增筆記，正文貼上 `==保留== 中文🎬選字 後文`，等狀態顯示已儲存。
2. 在編輯模式選取 `中文🎬選字`，按 **更多 → 切換選取文字的螢光標記**。切回閱讀，只有選取部分應有黃色底色。關閉紙間，再啟動檢查同一篇。
3. 用 **檔案 → 備份工作區…** 另存 SQLite。將備份複製到第二個空白可攜測試資料夾的 `paperroom-data/notes.sqlite3`，同時放入同一份 EXE。以 `--portable` 啟動第二份 EXE，確認備份中的高亮仍可讀。
4. 在第二個工作區選 **檔案 → 匯出工作區 HTML ZIP…**。解壓到新資料夾，離線開啟 HTML，核對只有 `中文🎬選字` 被標示。ZIP 內的 Markdown 要逐位元符合原文，包含 `==保留==`。在編輯模式再次選取原範圍可以消除高亮。

## 關於與封裝

在合成工作區正常退出後記下 `notes.sqlite3` 的 SHA-256。再開啟紙間，從 **檔案 → 關於紙間／第三方補充通知…** 核對 Foxit、Adobe CMaps、ICC 色彩描述檔、alloc-stdlib 四個區段。關閉視窗並退出，資料庫的 SHA-256 應相同。

草稿驗收的暫存 ZIP 核對同一份 EXE、四份 PDF 補充通知和 Rust 標準函式庫版權通知。Rust 通知的 SHA-256 也要符合該 EXE 的建置紀錄。Cargo 相依解析與 CRT 連結標記另見這份紀錄。正式發行前仍需核對實際連結元件的再散布條款。暫存 ZIP 在驗收完畢後會刪除。
