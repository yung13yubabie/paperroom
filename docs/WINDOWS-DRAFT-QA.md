# 紙間 Windows 草稿驗收

這是一份待執行的人工驗收表，不代表候選已通過。使用獲准且乾淨的 Windows 10 或 Windows 11 x64 桌面，記錄實際系統版本、測試日期及結果。可取得兩個版本時分開記錄。Windows Sandbox、Windows Server 與 Wine 的結果屬補充資料，用戶端驗收要在對應的 Windows 桌面執行。只使用新建的合成筆記和獨立測試資料夾，不使用個人資料。紙間直接執行，無須安裝程式。

## 候選與測試身分

1. 從指定 CI 執行下載其草稿附件，記錄執行網址、來源 commit、附件名稱及 ZIP／EXE 的 SHA-256。解壓後用 PowerShell `Get-FileHash -Algorithm SHA256 .\Paperroom.exe`，與該次 CI 的 EXE 雜湊比較；複製到各測試資料夾後再次比對。若不同或無法取得可核對的結果，停止並回報。雜湊用於比對同一份檔案，不能單獨證明來源可信。
2. 使用本機標準使用者，確認帳戶不是系統管理員群組成員（包括透過其他群組的成員資格），記錄帳戶類型；以一般方式啟動 PowerShell 和 EXE，不選「以系統管理員身分執行」。在同一 PowerShell 執行 `([Security.Principal.WindowsPrincipal] [Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole([Security.Principal.WindowsBuiltInRole]::Administrator)`，結果應為 `False`。此結果只檢查目前權杖，不能單獨證明帳戶不是管理員；請一併核對帳戶群組。分享紀錄前遮去帳號、裝置名稱和 SID。
3. 下載與比對完成後，斷開 Wi-Fi 和有線網路；記錄斷線時點與介面狀態。以下首啟、搜尋、備份、還原、HTML 和關於畫面均在離線狀態操作，結束時再記錄狀態。這是操作條件的紀錄，不是全系統網路封包稽核。

## 預設位置與可攜工作區

1. 使用新建空白本機目錄，將同一份 EXE 放在沒有 `paperroom-data` 的子目錄；在該 PowerShell 行程內把 `$env:LOCALAPPDATA` 設為另一個新建空白的本機目錄，從該行程啟動 EXE。勿更動系統或使用者的永久環境變數。確認首次啟動成功，**檔案 → 開啟資料所在資料夾** 指向該測試位置的 `Paperroom`，建立合成筆記後正常關閉所有紙間視窗，再啟動確認內容保留。
2. 將同一份 EXE 複製到另一個新建空白目錄，在其旁建立空的 `paperroom-data`，以 `--portable` 啟動。確認資料位置為該目錄，建立合成筆記，正文輸入 `==保留== 中文🎬選字 後文`，等狀態顯示已儲存。搜尋 `中文` 並確認能找到該筆記；以 Windows 輸入法輸入繁體中文，確認內容正確。
3. 在編輯模式選取 `中文🎬選字`，按 **更多 → 切換選取文字的螢光標記**。切回閱讀，只有選取部分應有黃色底色；正常關閉所有視窗，再啟動確認內容、搜尋及高亮保留。

## 備份、還原與離線 HTML

1. 選 **檔案 → 備份工作區…**，在新的獨立目錄另存 SQLite。將備份複製到第三個空白目錄的 `paperroom-data/notes.sqlite3`，旁邊放入相同雜湊的 EXE，以 `--portable` 啟動；確認備份中的合成筆記、搜尋及高亮可讀。原工作區應仍可開啟。
2. 在還原的工作區選 **檔案 → 匯出工作區 HTML ZIP…**，解壓到另一個新目錄，保持離線開啟 HTML，核對只有 `中文🎬選字` 被標示。ZIP 中 Markdown 須逐位元符合原文，包括 `==保留==`；在編輯模式再次選取原範圍可消除高亮。
3. 正常退出後記下還原工作區 `notes.sqlite3` 的 SHA-256。再啟動紙間，從 **檔案 → 關於紙間／第三方補充通知…** 核對 Foxit、Adobe CMaps、ICC 色彩描述檔、alloc-stdlib 四個區段，關閉畫面並正常退出；比較資料庫雜湊，若不同則保存測試副本並查明原因。

記錄各步是否通過、實際現象、離線檢查、兩種資料位置及候選雜湊；失敗或未執行的項目明確標示。不要上傳含個人資訊的截圖或資料庫。第三方通知的證據範圍和正式發行前待辦見[再發佈盤點](REDISTRIBUTION.md)。
